# Agentic Workflow Designer

[English](README.md)

GitHub Agentic WorkflowsのMarkdown編集を支援する非公式のVS Code拡張機能です。設定・本文の見出し・ジョブを一覧から選び、標準のMarkdownエディターと並べて編集できます。Markdownを正本として扱います。GitHubによる公式提供や承認を受けた拡張機能ではありません。

## 導入

Windows 11、デスクトップ版VS Code 1.96以降、ローカルのGitリポジトリ、GitHub CLI、`gh aw`拡張が必要です。CLIのバージョンを固定せず、インストール済みのバージョンでコンパイルします。

GitHub CLIは[公式手順](https://cli.github.com/)で導入してください。最新のgh-aw拡張はご自身でインストールしてください。

```powershell
gh extension install github/gh-aw
gh aw version
```

VS Codeの拡張機能画面で「Agentic Workflow Designer」を検索してインストールできます。GitHub Releaseから`gh-aw-visual-editor-0.1.1.vsix`をダウンロードし、「拡張機能: VSIX からのインストール...」から導入する方法もあります。リポジトリのフォルダーを開き、「Agentic Workflows: 環境を確認」を実行してください。本拡張機能がツールを自動で導入・更新することはありません。GitHubで実行する際の認証やEngineの資格情報は、別途設定が必要です。

## 使い方

初めて作る場合は、[新規作成から進める練習手順](docs/first-workflow.ja.md)を参照してください。リポジトリを調査して改善レポートを作る題材で、指示・設定・生成ジョブを一通り確認できます。

「Agentic Workflows: Workflowを新規作成」を実行し、テンプレートとファイル名を指定します。テンプレートは最小ひな形、リポジトリ調査、Issue整理、定期レポート、既存文書の複製から選べます。ファイル名に`.md`を付ける必要はありません。複数フォルダーを開いているワークスペースでは保存先を選択します。ファイルは`.github/workflows/`配下に作成され、既存のファイルを上書きすることはありません。

[2つのAWサンプル](sample/README.md)も同梱しています。ほかのリポジトリで使う前に、参照先のスクリプトや権限を確認してください。

![Documentation reviewのMarkdownと設定画面](images/doc-consistency.png)

Documentation reviewのサンプルでは、Markdownと設定画面を並べて確認できます。

![Agentic PR Repairの独自ジョブ一覧](images/pr-agentic-repair.png)

Agentic PR Repairのサンプルでは、独自ジョブと依存先を確認できます。

既存ファイルを開く場合は、エクスプローラーでMarkdownファイルを右クリックし、「デザイナーを開く」を選択します。GUIと標準のMarkdownエディターが左右に並んで開きます。GUIで「適用」するとMarkdownに反映され、Markdownを直接編集した場合もGUIへ即座に同期されます。この右クリックメニューとエディター右上のボタンは、`.github/workflows/`配下のMarkdownでのみ表示されます。また、デザイナーがアクティブな間はエディター右上のボタンが非表示になります。それ以外のフォルダーにある文書は、コマンドパレットから開いてください。

| 表示 | できること |
|---|---|
| 設定 | 項目の一覧から選び、トリガー、Engine、ツール、権限、Safe Outputsなどを編集します。 |
| 本文 | セクションやサブエージェント・スキルの定義を追加し、一覧から選んで編集します。取り込み・実行情報・条件文の入力補助も使えます。 |
| ジョブとステップ | 独自ジョブは名前・実行環境・依存先・ステップまで作成できます。自動生成ジョブには対応する条件・追加依存先・権限・制限時間・ステップを設定できます。 |
| フロー図 | Markdownに明示されたジョブの依存関係と、gh-aw標準ジョブの予測を縦方向の図で表示します。ジョブを選ぶと対応する編集画面に移動します。破線はコンパイル時の推定動作を表します。 |

まず「本文」でエージェントに指示したい作業を記述し、「指示を適用」を押します。横に並んだMarkdownエディターで変更を確認してから「保存して確認」を押します。公式CLIが生成したYAMLを確認する場合は、コマンドパレットの「Agentic Workflows: 生成Workflowを開く」を使います。固定のシェルコマンドやActionの実行には「ジョブとステップ」の独自ジョブを使います。独自の`report`ジョブのように、実行環境・依存先・ステップ全体を定義できます。Markdown側で`jobs:`やジョブ名にカーソルを置くと、対応するジョブの編集画面が開きます。エージェントやSafe Outputsなどの自動生成ジョブでは、対応する設定のみを追加できます。Safe Outputsの機能設定へも、該当ジョブの画面から移動できます。

`uses:`を指定したActionステップを選択すると、`with:`の入力値を項目ごとに追加・変更・削除できます。文字列・数値・真偽値を指定できます。`uses:`を持つ既存の再利用Workflowジョブでも同様に入力欄が表示されます。複雑なデータ構造は該当するMarkdownへ移動して編集します。

自動生成ジョブに追加した依存先・条件・権限は、CLIが自動生成する値に加算・結合されます。生成ジョブ自体や必須の依存先を置き換えるものではありません。`setup-steps`は`activation`と`pre_activation`には追加できず、通常の`steps`も対応しているジョブにのみ表示されます。直近のコンパイル結果に含まれていない生成ジョブに設定を追加した場合、機能やトリガーの有効化が必要になることがあります。ファイルを保存してコンパイルを実行し、実際に生成されたジョブで確認してください。

指示のセクションはエージェントに渡す文章です。見出しごとにGitHub Actionsのステップやジョブが作られるわけではありません。本拡張機能はGitHub上でのリアルタイムな実行状況を表示しません。ソース変更後は再確認してください。

### 指示の入力補助

Agent Jobの「指示と定義を編集」から本文画面へ移動できます。「セクション・定義を追加」で種類を選び、名前と内容を入力します。サブエージェントでは説明とモデル、インラインスキルでは説明も指定できます。定義は通常のセクションとは分けて一覧に表示され、名前や内容の編集、並べ替え、削除が可能です。既存の定義のYAML設定は本文欄で編集でき、既存の他の項目も保持されます。

| 項目 | 入力補助と動作 |
|---|---|
| 通常のプロンプト | セクション名と指示の文章を入力します。 |
| サブエージェント | ``## agent: `reviewer` ``形式の定義と終了マーカーを追加します。任意の`description`と`model`を指定できます。 |
| インラインスキル | ``## skill: `review-checklist` ``形式の定義と終了マーカーを追加します。YAML設定の`description`に対応しています。 |
| 書式・出力例 | チェックリストや期待する出力例のコードブロックを挿入します。 |
| 外部コンテンツ | `{{#runtime-import .github/rules.md}}`を挿入します。公開HTTP(S) URL、行範囲、ファイル不在時の省略も指定できます。 |
| 実行情報 | リポジトリ名、実行ユーザー、IssueやPRの番号などを選び、`${{ github.repository }}`形式で挿入します。 |
| 条件付きプロンプト | 選択した文章を`{{#if ...}}`と`{{/if}}`で囲みます。Issue・PR・手動実行の条件を選べます。 |

「指示への入力補助」はカーソル位置へ挿入し、選択中の文字を置き換えます。「指示を適用」を押すまではMarkdownに変更が反映されません。未適用の指示がある場合は、それを適用してから新しいセクションや定義を追加してください。

サブエージェントとスキルの定義は実行時に親のプロンプトから取り出されます。定義を追加しただけでは自動的に呼び出されないため、親の指示文にも利用する名前を書いてください。定義に対応する`## end agent:`や`## end skill:`の終了マーカーが付くため、定義内に`##`見出しが含まれていても同じ定義として正しく扱われます。モデルや定義の利用方法はEngineによって異なります。詳細は[サブエージェントの公式仕様](https://github.github.com/gh-aw/reference/inline-sub-agents/)および[インラインスキルの公式実装](https://github.com/github/gh-aw/blob/v0.89.21/actions/setup/js/extract_inline_skills.cjs)を参照してください。

ファイルの取り込み先は`.github`フォルダー配下に限られます。条件の入れ子と`else`は使えず、本文の式ではシークレットや環境変数を参照できません。高度な式はMarkdownで編集し、インストール済みのCLIで確認してください。詳細は[テンプレートの公式仕様](https://github.github.com/gh-aw/reference/templating/)を参照してください。

ジョブ一覧では、ステップまで編集できる「独自ジョブ」と、対応する設定だけを追加できる「自動生成ジョブ」を分けて表示します。importsは参照として扱います。コマンドパレットから開く生成結果は閲覧専用です。

各フォームは「適用」で文書に反映します。「ソースへ移動」「Markdownを開く」は、並んでいる標準エディターを再利用します。GUIとソースは同じ文書とUndo/Redoの履歴を共有します。Markdownでカーソルを動かすと、GUIも対応する設定や本文を選びます。未適用の入力中はカーソルに追従しません。新規作成、生成YAML、環境確認はコマンドパレットからも実行できます。

Ctrl+SではMarkdownファイルのみを保存します。「保存して確認」は対象ファイルと必要なローカル依存ファイルを保存して、リポジトリ内で公式CLIを実行します。進行通知から中止できます。コマンドパレットの「Agentic Workflows: 生成Workflowを開く」では現在の生成物、最後の正常生成物、実行前の退避を読み取り専用で開けます。読み取り用の文書を別名で保存しても、元のlockファイルは更新されません。

設定フォームでは、名前・説明、手動・Issue・PR・cronのトリガー、Engineとモデル、GitHub・bash・editツール、明示的な権限、4種類のSafe Outputs、ネットワークの許可先、制限時間を編集できます。Issue・PRのイベント、Engine、GitHub toolsets、コメントの対象、ネットワークの許可先には候補があります。候補を選んで追加し、「適用」でMarkdownに反映します。固有のラベルやドメインなどは直接入力できます。機能を無効にすると、その子項目は隠れます。

GUIに未対応の項目は「その他の設定」に名前を表示します。「Markdownで編集」でその行へ移動でき、JSON全体を読む必要はありません。alias、merge、コメント付きコレクション、複数行文字列など、安全に変更できない形式にもソース編集のボタンを表示します。詳細は[対応範囲](docs/compatibility.md)と[制約事項](docs/limitations.md)を参照してください。

言語設定がない場合、画面はVS Codeの表示言語に従います。デザイナー上部には「日本語」「English」の2つのボタンがあり、再読み込みせずに切り替えられます。選択はユーザー設定`ghAwDesigner.language`に保存されます。再びVS Codeの表示言語に合わせるには、この設定を既定値に戻します。未適用のフォーム入力やMarkdownは切り替えても変わりません。コマンドパレットや右クリックメニューなど、VS Codeが表示するコマンド名は引き続きVS Codeの言語に従います。配色、フォーカス表示、入力欄のラベルもVS Codeの利用環境に合わせています。`on`がない共有コンポーネントは編集できますが、単独ではコンパイルせず、参照元のWorkflowからコンパイルします。

## 生成物の状態と信頼

ソースの保存とコンパイルの状態を分けて表示します。設定変更、本文だけの変更、依存変更、処理中、失敗、処理中の再編集を区別します。正常コンパイルの記録がない既存lockファイルは「対応未確認」です。開き直した際には記録したハッシュを現在のファイルと比較します。リモート参照は未展開であり、最新状態を検証済みとは表示しません。

同名の`.lock.yml`があれば、拡張の成功記録と一致しなくても「Agentic Workflows: 生成Workflowを開く」から閲覧できます。この場合は「lock YAMLあり・拡張の成功記録とは不一致（対応未確認）」と表示し、ファイル不在とは区別します。正常にコンパイルした際のCLIバージョンも記録します。

CLIはシェルを介さず、`gh aw compile --json --no-check-update <ソース>`を実行します。lock YAMLのほか、`.gitattributes`、`.github/aw/actions-lock.json`、高度な設定に必要な補助ファイルを変更する場合があります。生成物や補助ファイルが未保存の場合、または監視開始後に外部で変更された場合は実行を止めます。変更を確認し、ワークスペースを開き直してから再実行してください。

失敗してもリポジトリ内の変更を自動では戻しません。最後の正常生成物はVS Codeの拡張保存領域に残します。リポジトリ全体の原子的な更新や、バックアップ・バージョン管理の代替は保証しません。

未信頼ワークスペースでも編集できますが、環境確認を含め外部コマンドは実行しません。拡張は`init`、`fix`、`approve`、Git操作、Workflow実行を行わず、独自サービスに本文を送信しません。公式CLIが依存の取得などでネットワークを使う場合はあります。コンパイル成功は、GitHubでの実行成功や安全性の承認を意味しません。
