# Limitations

- The helper shows declared jobs and dependencies. Imports and omitted dependencies remain unexpanded; open generated YAML from the command palette to inspect the official compiler's resolved jobs and steps. Remote dependencies are not continuously verified.
- The optional Flow view draws declared `needs` and expected built-in jobs from the Markdown and previously observed gh-aw behavior. Dashed jobs and edges are predictions, not compiler output or a live run. New CLI releases and advanced settings may change these jobs; compile and inspect generated YAML for the exact graph.
- The `with:` form edits scalar inputs on `uses:` steps and existing reusable-workflow jobs. Nested input values, aliases, merges, anchors, and commented removals require source editing.
- Instruction headings are Markdown sections, not guaranteed runtime stages, branches or Actions jobs. The helper does not interpret arbitrary prose as executable control flow. Only `##` headings outside fenced code and HTML comments define editable section boundaries.
- Compiler-managed jobs accept only supported Markdown additions. Custom jobs, their dependencies and ordinary steps are editable. Matrix expansion, runtime conditions and live run status are not simulated.
- Generated YAML parsing is limited to 8 MB and 200 jobs. The last successful snapshot can be stale after edits or failures; its correspondence status is shown. Before any successful compilation, an existing lock file is explicitly unverified.
- The custom/generated distinction describes which Markdown settings the user can edit, not an execution trace or a complete compiler source map. Advanced source syntax that needs text editing is still a user definition.
- `on` absent means a shared component. Such a document has no standalone generated output in the editor. Compile its importing workflow.
- Complex expressions, advanced engine/tool objects, aliases, anchors, merges, multiline basic-setting values and commented collections may need source editing. Flow forms support multiline commands; structural moves of commented steps require source editing. Forms never rewrite the whole frontmatter. Unsupported settings are shown in declared values and are preserved.
- Each Apply or Remove is a document edit. Stale version requests are rejected. During syntax errors, the last valid outline is visibly stale and form edits are disabled. Pending form input is not saved until Apply; if the source changes, the form refreshes with a warning.
- Local dependencies are bounded to 500 files and must stay inside the selected repository, including resolved filesystem links. Compiler output directories cannot contain symbolic links. Missing and remote references remain the compiler's responsibility.
- The compiler runs in the original repository and may change multiple files. Preflight checks prevent known conflicts; other programs can still race the CLI after those checks. There is no repository-wide transaction or automatic rollback. External changes to observed output/auxiliary files require review and reopening the workspace.
- Successful snapshots and pre-run backups are stored locally under VS Code's extension storage. The pre-run backup is explicitly unverified. Only the most recent successful snapshot and most recent pre-run backup are retained per source URI. Clearing extension storage removes those backups, not source documents.
- Compile correspondence includes local content hashes, compiler version and generated output. Instruction-only changes have their own status. A remote ref can change independently, so the UI does not claim remote freshness. GitHub authentication, runtime credentials and successful GitHub execution are separate concerns.
- Only structured, existing file/line locations from compiler diagnostics are attached to Problems. Unlocated messages remain in results and Output. A line number embedded only in a diagnostic's prose is not treated as verified metadata.
- Compiles within one repository are serialized within this extension host. Other VS Code windows and tools are independent. Cancellation terminates the child process tree on Windows; already-written files are not rolled back.
- Process output is capped at 8 MB per stream and compilation times out after three minutes. Environment probes time out after 15 seconds. Long-running or unusually large workflows can be compiled directly with the CLI.
- This extension does not initialize repositories, install/update tools, approve changes, run workflows, commit, push, or publish. A trusted workspace is required even for checking CLI versions.
